2.2 爬取方法

方法 A：wget 递归下载（主用）

wget \
  --recursive \                    # 递归
  --level=inf \                    # 深度无限
  --page-requisites \              # 包含页面所有依赖
  --html-extension \               # HTML 扩展名规范化
  --convert-links \                # 转换链接为本地
  --no-parent \                    # 不超出父目录
  --domains i2tools.com,oss-cdn.i2tools.com \
  --reject "*.webp,*thumb*" \      # 过滤部分大文件
  --user-agent="Mozilla/5.0..." \
  --tries=3 --timeout=30 \
  https://i2tools.com/

方法 B：Scrapling + patchright（备选，处理反爬与动态渲染）

from patchright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(
        headless=True,
        args=['--no-sandbox', '--disable-dev-shm-usage',
              '--proxy-server=http://127.0.0.1:18080']
    )
    ctx = browser.new_context(locale='zh-CN')
    page = ctx.new_page()
    page.goto('https://i2tools.com/', wait_until='networkidle')

    def on_response(resp):
        if resp.url.endswith('.js'):
            save_to_local(resp.body())
    page.on('response', on_response)

4.1 颜色匹配算法

来源：chunk 8071-30a1b464baed2037.js

⚠️ v3 修正：原「Median Cut 调色板提取 + K-D Tree 7 叉树加速」为推测，实际算法是朴素线性扫描 + Map 缓存（chunk 8071 反编译 for(let e of c){…}，无 kdTree/medianCut 关键字命中）。调色板来自固定 MARD 221 色（chunk 9350 brands.mard.definitions），并非运行时提取。
算法用途关键点
Median Cut调色板提取v3 修正：不存在，全部 72 个 chunk 0 命中 medianCut/kmeans/octree/quantization，调色板来自固定 MARD 221 色
K-D Tree最近邻加速v3 修正：不存在，实际是朴素线性扫描 + Map 缓存 CAM16-UCS 转换结果
DeltaEHybrid颜色距离CIE Delta E 混合算法（chunk 8071 e.DeltaEHybrid="delta-e-hybrid"）
CAM16-UCS颜色距离（默认）更符合人眼感知；chunk 8071 findClosestPaletteColorCam16Ucs 实现，朴素 for 循环扫描调色板 + Map 缓存

4.4.2 8 连通域分析（经典 BFS 队列扩散）

✅ v3 修正：8 连通扫描方法已确认为经典 BFS 队列扩散（q.shift() 出队 + q.push() 入队），配合 new Uint8Array 标记矩阵 + u(t) 4/8 连通选择器。test_denoise_apply_v3.py 实测色号 49→45 真实执行（dn_after_apply.png）。 
// 4 连通：[[-1,0],[1,0],[0,-1],[0,1]]
// 8 连通：[[-1,-1],[-1,1],[1,-1],[1,1]] 补充
let u = e => 4===e ? d : c;  // 4 or 8

// 经典 BFS 队列扩散标记同色像素为同一区域
function g(e, t=8) {
  let r = u(t), n = Array.from({length:e.length}, () => new Uint8Array(e[0].length));
  for (let row=0; row<e.length; row++) {
    for (let col=0; col<e[0].length; col++) {
      if (n[row][col]) continue;
      let q=[{row,col}];
      while (q.length) {
        let p = q.shift();  // ⭐ 经典 BFS 出队
        for (let [dr,dc] of r) {
          let nr=p.row+dr, nc=p.col+dc;
          if (!n[nr][nc] && same_color(e[nr][nc], e[p.row][p.col])) {
            n[nr][nc]=1; q.push({row:nr, col:nc});  // ⭐ 经典 BFS 入队 + 标记
          }
        }
      }
    }
  }
}

4.4.3 面积阈值过滤

参数：areaThreshold ∈ [1, 12] step 1

含义：连通域像素数 < 阈值 → 视为杂色 → 删除/合并到邻域。

4.4.4 接触率保护

参数：minContactRatio ∈ [0, 0.9] step 0.05

含义：杂色区域与主体像素的接触比例，过低才删除（保护线条）。

E.1 外层 JSON 容器

E.3 AES-GCM-256 解密

  • IV = Base64 解码后前 12 字节
  • 密文 = 剩余字节
  • 算法 = AES-256-GCM（带认证标签）

解密流程（decode_pbp.js 核心片段）：

// 1. 解析外层 JSON
const outer = JSON.parse(raw);
// 2. Base64 解码 data
const buf = Buffer.from(outer.data, 'base64');
// 3. 拆分 IV(前12字节) + 密文(剩余)
const iv = buf.subarray(0, 12);
const ciphertext = buf.subarray(12);
// 4. PBKDF2 派生密钥
const key = crypto.pbkdf2Sync('perler-beads-project-v1', 'perler-salt', 100000, 32, 'sha256');
// 5. AES-256-GCM 解密
const decipher = crypto.createDecipheriv('aes-256-gcm', key, iv);
const plain = Buffer.concat([decipher.update(ciphertext), decipher.final()]);

E.5 ⚠️ 重要安全发现：固定密钥 = 混淆而非真加密

所有 .pbp 文件使用同一把固定密钥（password/salt/iterations 全部硬编码），任何拿到 .pbp 的人都能用相同参数解密。这实质上是「混淆」(obfuscation) 而非真正的加密保护——无法防止有技术能力的用户读取项目数据。

I.8 反爬破解要点(对接建议)
